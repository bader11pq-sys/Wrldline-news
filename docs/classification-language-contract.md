# WRLDLINE classification, language and translation contract

WRLDLINE keeps four dimensions separate. Mixing them caused the earlier `world` and `دولي` defaults, the misleading "translation" label on original text, and the duplicated classification workers.

| Dimension | Field | Meaning |
| --- | --- | --- |
| UI language | `language.js`, `document.documentElement.lang/dir` | The language the reader chose or the browser suggested. It does not describe the article. |
| Source language | `articles.source_language`, `articles.lang` | The language the publisher actually wrote in. `lang` is kept as a compatibility mirror. |
| Translation | `article_translations.translation_status/source` | Whether a translation exists, who produced it, and whether it is public. |
| Story classification | `articles.category`, `topics`, `geographic_scope`, `event_country` | What the story is about, where it happens, and how confident the classifier is. |

## Categories

The allowed categories are `politics`, `economy`, `security`, `tech`, `sports`, `culture`, `health`, `science`, `environment`, `society`, `world`, and `uncategorized`.

A database trigger normalizes unknown values to `uncategorized`. It never promotes them to `world`. A feed's category is the source section signal; a general feed is `uncategorized` until an editor or the AI classifier assigns a topic. `world` is reserved for stories that are genuinely cross-border or centered on international relations, not for every international publisher.

The classifier accepts a topic only at confidence `>= 0.72`. A suggestion at `>= 0.55` can be stored for review, but the article status becomes `needs_review`. Below that threshold the article stays `uncategorized`.

## Source language

`resolveSourceLanguage(declared, text)` gives the declared feed language priority. Title/summary detection is a check, not a silent replacement. A mismatch is recorded as `language_detection = 'conflict'` while the declared language is preserved. Legacy rows are marked `legacy`.

The UI shows one of these labels instead of calling every text a translation:

- `النص الأصلي — العربية` / `Original text — Arabic`
- `النص الأصلي — الإنجليزية` / `Original text — English`
- `ترجمة آلية منشورة` / `Published machine translation`
- `ترجمة تحريرية معتمدة` / `Verified editorial translation`
- `ترجمة قيد المراجعة` / `Translation under review`

The article disclaimer is generated by `provenanceNote()` and matches the actual state.

## Source scope vs geographic scope

`source_scope` describes the publisher's reach: `local`, `national`, `regional`, `international`, `cross-border`, or `unknown`. `geographic_scope` describes the story. A national outlet can publish an international story; the two fields must not overwrite each other.

`country` is the event country when known. It is stored as `NULL` when unknown. `event_country` is the explicit event-country field; `source_country` is the publisher's country. The pseudo-values `دولي` and `غير محدد` are no longer written by ingestion.

## Translation lifecycle

`translation_status` is one of `none`, `draft`, `review`, `published`, or `rejected`. `translation_source` is `editorial`, `machine_draft`, or `external_source`.

New machine translations are written as `review` and are hidden from anonymous readers. Existing translations were grandfathered as `published` machine translations so the public site did not lose content, but the UI labels them honestly. An editor can promote a translation to `published` and set `translation_source = 'editorial'` after review.

## Classification queue

The single scheduled path is the Supabase cron job `wrldline-ai-classification-worker`, which runs every minute and calls `classify-news-worker`. The worker:

1. Expires queue rows older than 48 hours.
2. Releases claims older than 15 minutes.
3. Claims up to 20 rows atomically with `FOR UPDATE SKIP LOCKED`.
4. Calls `classify-news` in batches of 10 with `allow_backlog: true`.
5. Records `classification_attempts`, `classification_retry_after`, and `classification_last_error`.

Queue states are `pending`, `processing`, `failed`, `classified`, `needs_review`, `expired`, and `skipped`. Rows older than 48 hours become `expired`; Telegram ticker rows become `skipped`; failed rows use bounded exponential backoff and stop at five attempts.

GitHub Actions `bot.yml` and `ai-backlog.yml` are now manual `workflow_dispatch` fallbacks only. They no longer run on a schedule, so they cannot race the Supabase cron.

## Backfill and audit

`classification_backfill_audit` records the old and new category, country, source scope, language, and status before each backfill change. The backfill migration remapped 91 feed categories, 129 feed scopes, 5,487 article categories, and expired 972 old queue rows.

## Deployment

Apply migrations in order, then deploy the Edge Functions:

```bash
supabase db push
supabase functions deploy wrldline-news-ingest --no-verify-jwt
supabase functions deploy classify-news --no-verify-jwt
supabase functions deploy classify-news-worker --no-verify-jwt
supabase functions deploy translate-articles --no-verify-jwt
```

`--no-verify-jwt` is intentional: the ingestion and classification workers authenticate with `x-wrldline-cron-secret`, and `classify-news` validates the service-role key or an editor/admin session inside the function.
