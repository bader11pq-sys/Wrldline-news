# تحسينات أمان WRLDLINE — 15 نوفمبر 2026

كان مشروع الإنتاج يسمح لدور `anon` بإضافة أخبار إلى `articles` بشرط اختيار الحالة `published`. هذا الشرط لا يثبت أن العميل غرفة أخبار موثوقة. ترحيل `20261115060000_form_security.sql` يزيل سياسة الإدخال المجهول ويمنع تعديلات `anon` على الأخبار والترجمات؛ تبقى وظائف إدخال الأخبار على الخادم مستخدمة مفاتيح الخدمة الخاصة بها، والمحررون خلف أدوار Auth وRLS.

نقطة `contact-submit` تتحقق من الموافقة والحقول والأطوال، تحد قراءة جسم الطلب، وتستخدم عدادات ذرية لبصمات HMAC متجددة بدل حفظ البريد أو IP الخام في جدول المعدل. إلغاء الإدخال المباشر إلى `contact_messages` يمنع تجاوز هذه الطبقة عبر PostgREST. Origin/CORS لا يغنيان وحدهما عن مكافحة الروبوتات؛ تحديد المعدل يقلل الإساءة ولا يلغيها، وقد يحتاج الحجم الكبير إلى Turnstile مستقبلًا.

تُحفظ مفاتيح VAPID وسر توقيع رموز النشرة في Supabase Vault. دالة `notification_runtime_config()` متاحة لـ`service_role` فقط. لا تُحفظ القيم في Git أو ملفات المتصفح أو تقرير التسليم. المفاتيح العامة وحدها يمكن عرضها لتسجيل Push، ولا ينبغي إعادة توليد المفاتيح عند كل نشر لأن الاشتراكات السابقة تعتمد عليها.

أضيفت قاعدة Cloudflare خاصة بالنطاق الأساسي لإرسال `X-Content-Type-Options: nosniff` و`X-Frame-Options: SAMEORIGIN` و`Referrer-Policy: strict-origin-when-cross-origin` وتعطيل الكاميرا والميكروفون والموقع الجغرافي غير المستخدمة. سياسة CSP الأساسية للصفحات القديمة تمنع الكائنات وتقيّد base/frame دون منع السكربتات القائمة. سياسة صفحات SSR الجديدة أشد وتدار داخل العامل؛ ليست السياسة القديمة حماية كاملة من XSS. بقيت مسارات عامل API والنطاق الفرعي دون تغيير.

تثبت نسخة المتصفح المحلية من Supabase على الإصدار `2.119.0` بدل روابط `@2` المتغيرة، مع ترخيص وبصمة SHA-256. تحديث المكتبة لاحقًا يحتاج اختبارات المصادقة والتعافي، وليس تغيير الإصدار تلقائيًا.
