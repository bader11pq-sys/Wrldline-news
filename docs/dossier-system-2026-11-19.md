# نظام ملفات الأحداث الحية — WRLDLINE

تاريخ الإصدار: 19 نوفمبر 2026
الحالة: منشور على الموقع العام (GitHub Pages) ومغطى باختبارات بناء.

## 1. ما الذي أُضيف؟

منتج تحريري مركزي جديد: **ملف الحدث الحي (Live Event Dossier)**. صفحة ثابتة لكل حدث تجمع:

- لمحة سريعة: الطرف الأساسي، الموقع، تاريخ البدء، آخر تحديث، حالة الملف.
- ماذا تغيّر؟ قائمة تغييرات مؤرخة، مستقلة عن الخط الزمني.
- خط زمني يفصل **وقت الحدث** عن **وقت نشر المعلومة** (`reportedAt`).
- ميزان الروايات: اتفاق، اختلاف، وغير متحقق.
- السياق: خلفية سياسية أو اقتصادية أو تاريخية.
- الأثر على السعودية والخليج: أثر فعلي مقابل أثر محتمل.
- ماذا نراقب تالياً؟ مؤشرات ومواعيد.
- المصادر: ناشر، عنوان، رابط، تاريخ نشر، تاريخ وصول، ونوع المصدر.
- سجل التحديثات وسجل التصحيحات.

كل عبارة جوهرية تحمل مرجعاً إلى مصدر (`sourceRefs`)، وحالة تحقق ظاهرة:
`verified` (متحقق)، `reported` (منقول)، `claimed` (ادعاء)، `estimated` (تقدير)، `unverified` (غير متحقق).

## 2. البنية

```
content/dossiers/*.json      محتوى الملفات (مصدر الحقيقة التحريري)
scripts/build-dossiers.mjs   التحقق + توليد الصفحات والفهرس وRSS وsitemap
dossier.css                  تصميم الصفحات (RTL، هاتف أولاً، وضع ليلي، طباعة)
dossier.js                   تحسين تدريجي: المتابعة، المشاركة، الطباعة، ربط الأخبار
dossier/                     المخرجات المولدة (تُنشر كما هي)
tests/dossier-build.test.mjs اختبارات العقد والأمان والمخرجات
```

الأوامر:

```bash
node scripts/build-dossiers.mjs     # بناء كل الملفات
node --test tests/dossier-build.test.mjs
```

## 3. عقد المحتوى

التحقق يرفض البناء عند:

- `slug` غير صالح أو مكرر.
- `status` غير معروف (المسموح: `active`, `monitoring`, `closed`).
- `summary` أقل من 80 حرفاً أو أكثر من 900.
- مصدر برابط غير `https` أو معرّف مصدر مكرر.
- `sourceRefs` تشير إلى مصدر غير موجود.
- خط زمني أقل من 3 عناصر، أو تواريخ غير صالحة، أو `reportedAt` قبل `at`.
- قسم سياق بلا فقرات، أو بلا مرجع مصدر.
- عنصر في «ماذا نراقب» بلا سبب.
- نص فيه علامات HTML خام تُفسَّر كوسوم (يُسمح بالنص، ويُهرَّب عند العرض).

التوليد يهرّب كل النصوص في HTML، ويحوّل `<` في JSON-LD إلى `\u003c` لمنع كسر السكربت.

## 4. إضافة ملف جديد

1. أنشئ `content/dossiers/<slug>.json` وفق المخطط.
2. استخدم مصادر يمكن فتحها، وسجّل `accessedAt`.
3. لا تضع رقماً بلا مصدر، ولا تدمج حدثين مختلفين.
4. استخدم `claimed` أو `unverified` لكل ما لم يتحقق منه بشكل مستقل.
5. شغّل البناء والاختبارات.
6. راجع الصفحة على الهاتف وسطح المكتب قبل النشر.
7. حدّث `updatedAt` وأضف سطراً في `updates`.

## 5. قرارات تصميم

- **لا JavaScript إلزامي**: الصفحة كاملة المحتوى في HTML. JS يضيف المتابعة والمشاركة وربط الأخبار فقط.
- **ربط الأخبار محافظ**: يطابق كلمات المفتاح في العنوان والملخص من آخر 80 خبراً منشوراً، ولا يعرض خبراً غير مرتبط لملء المكان.
- **الأولوية التحريرية**: حقل `priority` يحدد ترتيب الظهور في الفهرس والرئيسية، ثم الحالة ثم تاريخ التحديث.
- **الوضع الليلي والطباعة**: متغيرات CSS، وتجاوزات طباعة تُظهر كل الأقسام وتطبع روابط المصادر.
- **SEO**: `canonical`، Open Graph، JSON-LD (`AnalysisNewsArticle` + `BreadcrumbList`)، sitemap مستقل، وإدخال في `robots.txt`.

## 6. ما لم يُنفَّذ بعد

- تحرير الملفات من لوحة إدارة (حالياً JSON في المستودع).
- توليد تلقائي من عناقيد الأخبار (يحتاج مراجعة بشرية قبل النشر).
- تنبيهات بريدية عند تحديث ملف يتابعه المستخدم (المتابعة محلية على الجهاز).
- ترجمة إنجليزية كاملة للملفات (الواجهة عربية أولاً).

هذه ليست وعوداً منشورة، بل عمل لاحق مشروط بالطلب والاستخدام.
